## Overall Impression

The page is coherent and on-brand. A developer recruiter landing here will understand Gildo's experience within 20 seconds. The bilingual toggle + dual PDF download is genuinely differentiating. The biggest failure is the **download CTA having no feedback loop** — the primary conversion action of the entire page is silent during the API call and during errors. That alone drops the score meaningfully. The secondary issue is **visual redundancy**: detail rows and tech badges duplicate information.

## What's Working

1. **Bilingual architecture**: PT/EN toggle affecting all content, plus two explicit download buttons, is genuinely useful to both domestic and international recruiters. This is not standard in portfolios.

2. **Current role emphasis**: Amber on Thoughtworks + `● active` badge creates an instant visual anchor. A recruiter scanning in 5 seconds knows where you are right now.

3. **Typography hierarchy**: Barlow Condensed name at display scale, amber title, mono metadata — the header identity reads clearly and aligns with the rest of the portfolio.

## Priority Issues

**[P1] Download buttons are completely silent during and after the API call**
- **What**: `DownloadButton` renders as a plain `<a href>`. During the ~200-1000ms API call, nothing changes. If the server fails, nothing happens. User has no idea if anything is working.
- **Why it matters**: This is the primary conversion action on the page. A confused recruiter clicks twice, gets two tabs, abandons. Or the server returns 500 and they think the page is broken.
- **Fix**: Convert to a `<button>` with `onClick` that calls `fetch()`, shows a loading state (spinner + "Gerando..." / "Generating..."), then triggers a blob download. Wrap in try/catch to show a brief error message on failure.
- **Suggested command**: `/impeccable harden app/resume`

**[P1] No active language indicator**
- **What**: When the page loads, there's no visible indicator of which language is currently active. An international recruiter who lands via direct URL doesn't know if they're reading English or Portuguese. The toggle is in the nav (which is off-screen on first scroll), not on the resume page itself.
- **Why it matters**: The page's unique value is bilingual content. If the user can't tell which language they're in, they'll miss the toggle entirely.
- **Fix**: Add a compact language indicator near the download buttons — either highlight the active download button differently, or show a small "Viewing: EN / PT-BR" label.
- **Suggested command**: `/impeccable harden app/resume`

**[P2] Detail rows + tech badges duplicate information**
- **What**: Each experience entry shows both labeled detail rows ("Languages: JavaScript, Java") and a tech badge row showing the same stack. The detail rows add categorization (Languages vs CI/CD vs Agile) but the badge row strips that context anyway.
- **Why it matters**: Cognitive load. A recruiter reads the description, then reads the detail rows, then reads the badges — three passes over largely the same data.
- **Fix**: Choose one pattern per purpose: keep detail rows for tooling context (CI/CD pipeline, agile tools) and remove tech from detail rows entirely, letting the badges carry the pure stack. Or remove the badge row entirely and rely on detail rows with badge styling.
- **Suggested command**: `/impeccable distill app/resume`

**[P2] Long page with no section anchors**
- **What**: Six sections, no `id` attributes, no in-page navigation. Cannot link to `/resume#experience`. No sticky mini-nav.
- **Why it matters**: Recruiters share sections with colleagues ("check out his experience section"). No deep linking means the entire page must be re-scrolled every time.
- **Fix**: Add `id` to each `<section>` matching the slug (`id="summary"`, `id="experience"`, etc.). Optionally add a sticky progress bar or floating section dots for long-scroll navigation.
- **Suggested command**: `/impeccable harden app/resume`

**[P3] "← Back to site" buried at the bottom**
- **What**: The only navigation back to the portfolio is after certifications — requires scrolling through the entire resume.
- **Why it matters**: A recruiter who lands directly on /resume via LinkedIn and wants to explore the full portfolio has to scroll past everything to find the exit.
- **Fix**: The sticky nav already has the `<GN/>` logo linking to `/`. That's sufficient for keyboard users and scrollers. But adding a subtle "← gildoneto.vercel.app" breadcrumb below the `./resume` terminal label at the top of the page would solve this cleanly.
- **Suggested command**: `/impeccable harden app/resume`

## Persona Red Flags

**Jordan (International Recruiter arriving via LinkedIn)**
Landing on /resume for the first time. Primary action: understand experience, download PDF.
- Sees `./resume` at top — understands it as a nav breadcrumb, moves on. OK.
- Sees `./summary` above "Professional Summary" — reads as redundant label, not a problem but not adding value.
- Clicks "↓ EN" — waits. Nothing. Clicks again. Two downloads start. Confused.
- Wants to go back to the portfolio — scrolls all the way to the bottom — finds "← Back to site" after certifications.
- **Red flags**: No download feedback; "PT-BR" label may be unclear ("Is this Portuguese?"); back nav buried.

**Casey (Mobile Recruiter, one-handed, 4G)**
Opening /resume from a WhatsApp link.
- Header photo + name renders in `flex items-start gap-6` — on 375px screen the 80px photo stays left while the 4rem name beside it is compressed — may wrap awkwardly.
- Download buttons are in the upper half of the screen on mobile — far from thumb zone.
- Detail rows with `w-24 shrink-0` label column: 24 * 4px = 96px label beside remaining content — may be tight on 375px.
- **Red flags**: CTAs not in thumb zone; header layout potentially awkward at 375px; no lazy loading concern (photo is 80px, optimized).

**International Recruiter (project-specific — from PRODUCT.md)**
US/EU-based founder evaluating Gildo for a contract.
- Landing language: unknown (depends on browser `navigator.language`). May land in PT-BR even though they don't speak it.
- No clear indicator of current language on the page body.
- Sees "↓ PT-BR" and "↓ EN" — understands EN immediately but "PT-BR" requires inference ("Brazil Portuguese?").
- **Red flags**: Language auto-detection may silently serve PT-BR to an EN speaker; "PT-BR" label unclear without context; no inline language switcher on the resume page itself (nav toggle is far up the page).

## Minor Observations

- `mb-8` on `SectionHeading` (32px gap between heading and content) is generous — could be tightened to `mb-5` or `mb-6` for tighter document rhythm.
- Certifications: 9 items is a lot. The list could be compressed by removing "Udemy" issuers (implied by the course title) or grouping by category.
- The `● active` badge uses `text-amber/70` (70% opacity amber). This probably doesn't render via CSS `color-mix()` correctly in all browsers with OKLCH tokens — worth verifying visually.
- `SUMMARY.paragraphs` last item parsing hack (`p.pt.replace("Atualmente na Thoughtworks,", ",")`) is fragile — if the copy changes, the amber span breaks.
